# 小厨宝 使用说明

这份是上手前要看的一页：它是什么、三个按键怎么操作、放着不管会怎样。设计取舍、
体积数字与资源打包流程在 [`README.zh_CN.md`](README.zh_CN.md) 里，本页只讲用法。
改动历史见[更新日志](CHANGELOG.zh_CN.md)。

## 简介

小厨宝把 AI Passport 变成一本装在口袋里的菜谱，全程不联网。固件里自带 340 道社区
收集的家常菜——菜名、品类、配料行、编号步骤——以及 177 张成菜实拍图。没有 Wi-Fi
配网、没有账号、没有服务器，也没有文件系统：菜谱文字与图片在构建时就已经打进固件，
所以放在厨房抽屉里、在没信号的车上，都能照常用。

之所以装得下，是因为没有东西是提前解码的。照片以基线 JPEG 存放，由 LVGL 内置的
tjpgd 按行解码，整帧数据永远不会落进 ESP32-C3 的内存。中文用的是按"界面真正会显示
的字"裁出来的三份字体子集，而不是整套中文字体。

两种进入方式，看你今天有多果断：

- **不知道吃什么？** 让它替你抽一道。
- **心里有数？** 直接翻列表，打开那道菜。

## 需要什么

- 一台 AI Passport（ESP32-C3、240×320 屏幕、上/下/确定三个按键）。
- 烧录一次 `feature/cook-like-hoc` 分支的固件。之后开机直接进应用，不需要先过一
  层演示菜单。
- 别的都不需要：不要手机，不要网络，不要存储卡。

三个按键就是全部交互。每个键都区分**短按**与**长按**（约半秒），六个手势覆盖整个
应用。息屏状态下，第一次按键只负责唤醒，不会顺带执行动作——所以绝不会出现"按一下
醒来就直接跳了页"的情况。

## 页面一览

| 页面 | 显示什么 | 底部提示条 |
| --- | --- | --- |
| **首页** | 标题、菜谱总数、两个按钮 | 有 |
| **随机页** | 封面图、菜名、品类 | 无 |
| **分类页** | 每屏九个品类，行尾是该品类的菜谱数 | 有 |
| **列表页** | 某个品类里的菜谱，每屏九行菜名 | 有 |
| **详情页** | 封面+菜名 / 配料 / 步骤 | 无 |
| **设置页** | 亮度、休眠时间、关于 | 有 |
| **关于页** | 项目、版本、作者、来源 | 仅一行提示 |

每页顶部都有一条状态栏。电量固定钉在右上角、不随页面移动；详情页的子页序号
（`1/3`、`2/3`、`3/3`）在同一条状态栏的左侧，正文页码（`n/m`）在右下角。

## 按键说明

### 首页

| 操作 | 结果 |
| --- | --- |
| 上/下 短按 | 在两个按钮间切换 |
| 确定 短按 | 进入高亮的按钮 |
| 确定 长按 | 进入设置页 |

### 分类页

从首页选「进入菜谱」先到这里。340 道菜分成 15 个品类，按源数据的目录顺序排列：
主食 32、凉拌 4、卤菜 11、早餐 35、汤 6、炒菜 71、炖菜 14、炸品 18、烤类 1、
烫菜 12、煮锅 11、砂锅菜 15、蒸菜 49、配料 40、饮品 21。

| 操作 | 结果 |
| --- | --- |
| 上/下 短按 | 选中项移动一行；越过本屏末行就加载下一屏并落在其首行 |
| 上/下 长按 | 整屏翻页 |
| 确定 短按 | 进入该品类的菜谱列表 |
| 确定 长按 | 回首页 |

### 随机页

| 操作 | 结果 |
| --- | --- |
| 上/下 短按或长按 | 换一道菜 |
| 确定 短按 | 看这道菜的做法 |
| 确定 长按 | 回首页 |

340 条里只有 279 条参与抽取。源数据还含 40 条调料（酱汁、汤底、油）和 21 瓶装饮品，
它们仍然能在列表里翻到，但拿来当推荐就很怪，因此由一张生成的索引表排除掉。

### 列表页

| 操作 | 结果 |
| --- | --- |
| 上/下 短按 | 选中项移动一行；越过本屏末行就加载下一屏并落在其首行 |
| 上/下 长按 | 整屏翻页 |
| 确定 短按 | 打开选中的菜谱 |
| 确定 长按 | 回分类页 |

页眉标题就是当前品类名，右上角是它在这个品类里的位置。翻页与选中的手感和分类页
完全一致——两页共用同一套分页逻辑。它永远不会翻出空屏：到本品类最后一道菜时选中
项就停住。

### 详情页

三个子页：**封面+菜名**、**配料**、**步骤**。

| 操作 | 结果 |
| --- | --- |
| 上/下 短按 | 当前子页整页翻一屏；翻到最后一屏再按就进入下一个子页 |
| 上/下 长按 | 上/下一个子页 |
| 确定 短按或长按 | 回到进来时的那一页 |

配料与步骤拆成两个子页而不是一条长滚动，是因为一道十八行配料的菜，读成"第 1/2
页"比无止境地滚要舒服。行首的圆点与序号是橙色的，正文是墨色。

### 设置页

| 操作 | 结果 |
| --- | --- |
| 上/下 短按 | 在条目间移动 |
| 确定 短按 | 亮度/休眠时间：切到下一档；关于：进入关于页 |
| 确定 长按 | 回首页 |

### 关于页

| 操作 | 结果 |
| --- | --- |
| 上/下 短按 | 滚动正文 |
| 确定 短按 | 回设置页 |

## 设置项详解

**亮度** —— 25% / 50% / 72% / 100%，写入 NVS，重启后仍然保留。光线暗的厨房可以调低；
屏幕是整机耗电的大头。

**休眠时间** —— 关闭 / 30 秒 / 1 分钟 / 5 分钟 / 10 分钟。到点后分两步走：

1. **关屏**：背光熄灭、面板进 Sleep In、LVGL 停止刷屏，界面原样留在 RAM 里；
2. **低功耗**（再过 5 秒）：ESP32-C3 反复进入 light sleep，只留一个每 120 毫秒醒
   一次的轮询等按键——三个按键共用一路 ADC 分压，只有读电压才能区分它们。

任一步按任意键都能立刻回到刚才正在看的那道菜。中间没有"休息中"页面：早期版本有
过一页，那页想显示时间，而这块板子上没有可信时钟。

这里用的是 light sleep 而不是 deep sleep：deep sleep 等于重启，页面状态得自己存档，
而且唤醒后要等一两秒开机；light sleep 保留 RAM，唤醒只是"接着跑"。代价是它只把整机
电流从几十毫安降到毫安级，而不是微安级——对一块 500mAh 的电池来说，放着不管能多撑
一两天。

**关于** —— 项目名、版本、作者，以及菜谱、字体、息屏思路各自的来源。

## 电量显示

右上角，每 5 秒刷新一次：一个百分比加一个电池外框，内部填充随电量变化。低于 20%
时两者一起变红。电量计没回应时显示 `--`，而不是编一个数字。精度取决于电芯与电池
profile，把它当指示器看，不要当校准结果。

## 构建与烧录

只在你要改应用时才需要；普通用户烧一次即可。

```bash
# 1. 重新生成菜谱表、封面 blob 与字符清单。
python3 tools/build_cook_assets.py

# 2. 依据字符清单重新生成三个字号的字体子集。
python3 tools/build_cook_fonts.py

# 3. 校验字形覆盖与资源自洽性。
python3 tests/test_cook_assets.py

# 4. 构建并烧录。
idf.py build
idf.py -p <PORT> flash
```

只要改了屏幕上出现的文案，第 1 步必须先于第 2 步：UTF-8 正确、编译通过，都不代表
字形存在，只有第 3 步和真机上的那一眼能证明。26px 标题字体用的是自己那一份小清单
（`assets/fonts/cook_chars_titles.txt`），只更新公共清单会让标题缺字。

## 已知限制

- 340 道里有 163 道没有实拍图，封面子页显示占位文字，做法文本是完整的。
- 菜谱文案逐字取自源仓库，包括它的用量说法。没有搜索、没有收藏、不能编辑——数据
  按设计就是只读的。
- 设备没有时钟，应用里没有任何与时间相关的行为。
- 不涉及音频，ES8311 由本应用保持不动。
